# Modelo 3C — Abordagens Preliminares

O modelo 3C (Cartão, Conversa e Confirmação) foi utilizado para documentar as histórias de usuário do Blabry. Cada requisito passou por uma conversa entre o P.O e o desenvolvedor antes de ser implementado, garantindo clareza nos critérios de aceitação.

Esta seção registra as abordagens preliminares sobre requisitos não funcionais relacionados ao frontend — performance, responsividade, acessibilidade, segurança e manutenibilidade.

---

## Performance

### Cartão

| Campo | Descrição |
|---|---|
| ID | RNF-F01, RNF-F02, RNF-F03, RNF-F04 |
| Como | usuário do Blabry |
| Quero | que a aplicação carregue rapidamente e responda de forma fluida |
| Para | ter uma experiência agradável sem esperas perceptíveis |

### Conversa

<ChatLog messages={[
    { autor: 'po', texto: 'Quando o usuário abre o Blabry pela primeira vez, quanto tempo ele pode esperar antes de ver a tela de login? E quando navega entre o feed e o chat, essa transição pode ter algum delay perceptível ou precisa ser instantânea?' },
    { autor: 'dev', texto: 'Ele não deve esperar mais que 2 segundos em condições ideais. De acordo com o tempo de resposta da API, até que esse retorno chegue, será mostrada uma animação de carregamento para que o usuário tenha um feedback sobre o status do sistema, segundo a primeira heurística de Nielsen: Visibilidade do Status do Sistema. Após essa espera, o usuário já estará pronto a realizar as primeiras ações: cadastro e/ou login.' },
    { autor: 'po', texto: 'E sobre as transições entre seções — essa animação de slide que aparece no design — ela pode ter um delay de até quantos milissegundos antes de parecer travada para o usuário?' },

No entanto, dependendo do desempenho do computador do cliente, um delay pode aparecer, mas não por decisão de design da aplicação. A regra é: usuário clicou, animação executa imediatamente.' }
